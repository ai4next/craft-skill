# 交互模式与图解布局

做 `diagram` 类型时读这份；其他类型需要交互设计时也可以查。

---

## 一、图解布局

craft 的 `diagram` 有六个子类型 —— `architecture` / `workflow` / `sequence` /
`dataflow` / `lifecycle` / `freeform`（字段与示例见 `diagram-model.md`）。

**前五种子类型的几何由运行时算，你不需要选布局。** 你只写拓扑（谁连谁、谁属于哪个分组），
分层、排序、坐标、正交路由、端口分配、标签避让、分组框全自动。

`freeform` 是唯一例外 —— 坐标由作者给，所以下面这张表只对 `freeform` 有用，
或者当你画的是不属于上述六类的概念图（解释一个想法、一段关系、一段历史）时。

### 布局选型（`freeform` / 概念图）

| 关系形态 | 布局 | 适用 |
|---|---|---|
| 层级 / 归属 | 树、缩进图、旭日 | 分类体系、组织结构 |
| 顺序 / 阶段 | 横向流程、时间线、漏斗 | 步骤、流水线、转化 |
| 网络 / 互相影响 | 力导向、环形、弧线图 | 概念关系、依赖 |
| 循环 / 反馈 | 环形 + 回边 | 闭环、正负反馈 |
| 对比 | 并列两栏、象限图 | 方案对比、优先级 |

### 硬规则

下面五条对**所有**图解成立 —— 自动布局的子类型里，运行时只能保证「不重叠、不交叉、
标签不被压」，**保证不了「这张图好读」**，那是你选拓扑时的责任。

前三条是**可读性建议**（checker 不管）；第 5 条括号里的是 checker 真会拦的硬上限。

1. **主路径唯一且明显。** 读者第一眼应该看到一条主线，而不是一堆节点。
2. **节点上限 12 个。** 超过就分层（概览图 → 点击展开细节）。
3. **边比节点少。** 边数 > 节点数 × 1.5 时，图会变成毛线球 —— 砍掉低价值的关系。
4. **方向一致。** 从左到右，或从上到下，不要混。自动布局的子类型用模型的
   `direction` 字段统一指定（`TB`／`LR`／`BT`／`RL`），别让个别边反向。
5. **文字要短。** 节点标签目标 ≤ 8 个汉字（硬上限 18，超了报 `model/label-budget`），
   边标签硬上限 12；长解释放 tooltip 或详情面板。

## 二、图解交互

运行时的 `data-*` 已经把交互接好了，你不用写事件监听：

```html
<div data-craft-diagram="architecture"
     data-craft-model="main"
     data-craft-diagram-label="订单系统运行时架构图"></div>
```

模型写在 `<script type="application/json" data-craft-data="main">` 里（≤6 个节点时也可以
退回属性写法）。**节点声明只给语义，不给几何** —— 框、标签、边全由运行时画：

```html
<g data-craft-node="intake" data-craft-node-group="前端"
   data-craft-node-label="入口" data-craft-node-kind="frontend"></g>
<path data-craft-edge="intake->parse" data-craft-edge-kind="flow"></path>
```

| 属性 | 含义 |
|---|---|
| `data-craft-node="<id>"` | 节点 id，页面内唯一 |
| `data-craft-node-label` / `-sublabel` | 主标签 / 副标签 |
| `data-craft-node-kind` | 节点种类，决定配色；取值见 `diagram-model.md` |
| `data-craft-node-group` | 分组 id，用于「高亮同组」 |
| `data-craft-node-pos` | **只有 `freeform` 用**（`x,y`）；其他子类型给了也会被忽略 |
| `data-craft-edge="a->b"` | 有向边，两端是节点 id |
| `data-craft-edge-label` | 边标签（≤ 12 字） |
| `data-craft-edge-kind` | **只有 `return` 有效果** —— 画成虚线，表示返回消息。其余取值不影响渲染 |

**不要手写 `<rect>` / `<text>` / 任何坐标** —— 框尺寸由标签算出来，节点元素由运行时生成。
你自己画的那份会被忽略，或者和运行时生成的重叠。

点击与悬停**自动生效，没有开关**：点节点 → `inst.focus(id)`（高亮 + 缩放过去），
悬停/聚焦 → `inst.hover(id)`（tooltip）。要接自己的逻辑就监听容器上的 `craft:focus`：

```js
document.querySelector('[data-craft-diagram]')
  .addEventListener('craft:focus', e => console.log(e.detail.id, e.detail.node));
```

**可聚焦性由运行时保证。** 它生成的节点已带 `tabindex="0"` + `role="button"` +
`aria-label`（由 `kind` + `label` + `sublabel` 拼出）。你写的声明元素只是**数据载体**，
不会被渲染 —— 所以**不要**在它上面加 `tabindex` / `aria-label` / 坐标，加了也没用。
纯装饰的 SVG 加 `aria-hidden="true"`。

## 三、交互模式库

按「读者想干什么」选，不要为了炫技加交互。

### 悬停提示（tooltip）

| | |
|---|---|
| **用于** | 补充细节，不打断阅读 |
| **不要用于** | 承载理解所必需的信息 —— 触屏没有 hover |
| **实现** | 图表：给元素加 `data-craft-mark`。图解：**什么都不用做** —— 悬停与键盘焦点已经接在运行时生成的节点上 |
| **注意** | 触屏和键盘用户拿不到 hover，所以关键信息必须有非悬停的获取路径（a11y 数据表、详情面板） |

### 点击选中 / 高亮

| | |
|---|---|
| **用于** | 在多个对象间聚焦，看某个的具体情况 |
| **实现** | 图解节点点一下就是 `inst.focus(id)`，高亮 + 缩放全自动；图表给元素加 `data-craft-mark` |
| **注意** | 选中态不能只靠颜色 —— 运行时已同时改描边与 `data-focus`；自己加状态时也要这样 |

### 刷选 / 缩放平移

| | |
|---|---|
| **用于** | 数据点很多、需要看局部 |
| **实现** | `data-craft-zoom="x"` 启用滚轮缩放 + 拖拽平移 + 双击复位 |
| **注意** | **必须提供复位方式**（双击或按钮）。读者缩放后迷路是常见挫败 |
| **不要用于** | 少于 30 个数据点的图 —— 全部能看见，缩放只是添乱 |

### 分步叙事

| | |
|---|---|
| **用于** | 有先后顺序的解释 |
| **实现** | `Craft.step` + `data-craft-step`，见 `explainer-craft.md` |
| **注意** | 不要用滚动位置做唯一触发器 —— 键盘用户走不动 |

### 搜索 / 过滤

| | |
|---|---|
| **用于** | 类别很多（> 20），读者要找特定的一个 |
| **实现** | 输入框 + `Craft.bind`，过滤后 `chart.update(filtered)` |
| **注意** | 过滤后要显示「N / 总数」的计数，否则读者不知道是不是全都在 |

### 深链

| | |
|---|---|
| **用于** | 想把某个状态分享给别人 |
| **实现** | 运行时已支持 `?theme=` 与 `#step=N`；自定义状态可用 `history.replaceState` |
| **注意** | 深链状态要在页面加载时正确恢复，不然分享出去的链接是坏的 |

### 动画

| | |
|---|---|
| **用于** | 表达「变化」本身（状态迁移、时序） |
| **实现** | `Craft.animate.to()` / `Craft.animate.tween()`，自动尊重 `prefers-reduced-motion` |
| **不要用于** | 装饰。持续的背景动画会分散注意力并耗电 |
| **注意** | 静态状态必须自解释 —— 不看动画也要能理解全部信息 |

## 四、交互的代价

每加一个交互，都要能回答：**「不加这个，读者会失去什么？」**

答不上来就删掉。一个只有 tooltip 的图，比一个有缩放、刷选、搜索、动画但每个都半吊子的图好用得多。

**交互三原则：**

1. **默认状态自解释** —— 读者什么都不做时，信息是完整的。
2. **可发现** —— 有交互的地方要有视觉提示（光标、下划线、按钮样式），别指望读者乱试。
3. **可逆** —— 任何改变状态的操作都要能撤销或复位。

## 五、自检

- [ ] 主路径一眼可见吗？
- [ ] 节点 ≤ 12、边不比节点多太多吗？
- [ ] 每个节点都能用 Tab 聚焦吗？焦点可见吗？
- [ ] 悬停才能看到的信息，触屏/键盘用户拿得到吗？
- [ ] 每个交互都答得上「不加会失去什么」吗？
- [ ] 默认状态下，图是完整的吗？
- [ ] 缩放/选中之后，能回到初始状态吗？
