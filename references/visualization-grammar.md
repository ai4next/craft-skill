# 数据可视化语法

做 `chart` 类型（含看板）时读这份。字段名与用法以 `references/authoring-contract.md` 为准。

---

## 一、先问「读者要做什么判断」

图表类型不该由数据形状决定，而该由**读者要做的判断**决定。

| 读者的判断 | 用 | 不用 |
|---|---|---|
| 谁更大 / 排序 | 条形图（横向，标签好读） | 饼图 |
| 怎么变的 / 趋势 | 折线、面积 | 柱状（除非只有 2-3 个时点） |
| 各部分占比 | 堆叠条形（横向） | 饼图、环形图（超过 3 类就读不出来） |
| 两个变量的关系 | 散点 | 双轴折线 |
| 分布 | 直方图、箱线、蜂群 | 平均值单值 |
| 密度 / 二维分布 | 热力图 | 散点（点太多会糊成一团） |
| 构成随时间变 | 堆叠面积、堆叠柱 | 多条独立折线（会互相压） |

**不要用双 Y 轴。** 两个量纲的刻度是任选的，能造出任何想要的「相关」假象。要比较就画两张图上下对齐、共享 X 轴。

---

## 二、选型细则

### 条形图 vs 柱状图

- 类别名是中文长词 → **横向条形图**（`data-craft-chart-type="bar"` + `data-craft-x-type="band"`，把类别放在 X 上横着排，或直接把 y 当类别）。文字横排永远比斜排好读。
- 时间序列用**柱状**时，柱子之间要留缝；连续时间用**折线**。

### 折线图

- 线宽 2px，圆角连接。别加阴影、渐变、发光。
- **数据点只在需要时画。** 点数 > 40 时不画点，只画线；靠 hover 提示。
- 多条线超过 5 条 → 改成「一图多条线 + 可切换」或「小倍数」（small multiples：每类一个小图，共享刻度）。

### 堆叠

- 只有**总和**也有意义时才堆叠。总和没意义就用分组柱。
- 堆叠顺序按大小排，最大的贴轴线。
- 段数 ≤ 5。超过就归并成「其他」。

### 热力图

- X 用 band，Y 用 `data-craft-series` 指定的分类字段。
- 色阶用 `sequential`；**零和负值要用发散色阶**（`diverging`）。
- 必须在图注里说明色阶含义（值 → 颜色），不能只放个色条不解释。

### 散点

- 点半径 3-4px，`fill-opacity` 0.6-0.8 —— 重叠时能看出密度。
- 点 > 500 个 → 降低透明度，或改用热力图。

## 三、坐标轴

| 规则 | 说明 |
|---|---|
| Y 轴从 0 开始 | 折线图可以例外（趋势看的是斜率），但要在图注里说明 |
| 刻度数 4-7 个 | 运行时自动选，别手动塞 |
| 刻度标签别斜排 | 挤了就把 X 换成 band + 横向条形图，或换更粗的时间粒度 |
| 单位写进轴标题 | `data-craft-y-label="新增用户（万人）"`，不要在每个刻度上写「万」 |
| 大数用紧凑格式 | 运行时自动：中文走 万/亿，英文走 K/M/B |

**绝不手算刻度。** `Craft.axis.render` 已经处理了 nice 数字、负区间、反转 domain、时间粒度。

---

## 四、颜色

三套令牌，按语义选：

| 场景 | 用什么 | 属性 |
|---|---|---|
| 分类（渠道、地区、类型） | `--craft-cat-0..7` | `data-craft-color="categorical"` |
| 连续量（密度、强度） | `--craft-seq-0..4` | `data-craft-color="sequential"` |
| 正负偏离零点 | `--craft-div-0..4` | `data-craft-color="diverging"` |

**分类色上限 8 个。** 超过就必须换编码方式（分组、小倍数），不要再造颜色 —— 人眼分辨不了。

**绝不只靠颜色区分。** 图例色块自带 `data-pattern` 图案线索（点线/虚线/实线边框），这是运行时提供的色盲友好兜底。用形状区分系列时也一样。

**语义色是陷阱。** 「红=下降、绿=上升」在不同市场含义相反。要么在图注里说清楚，要么别用。

---

## 五、标注

标注是图表信息密度最高的部分。**只标真正需要读者注意的点**：

- 拐点、异常值、政策生效日、版本发布日
- 最大值/最小值（如果那是重点）
- 阈值线（目标、红线）

标注超过 3 处，说明这张图想讲的事太多 —— 拆成两张。

**不要**给每个数据点都加标签。**不要**加网格线 + 数据标签 + tooltip 三重冗余。

---

## 六、看板（多图联动）

一个页面放多个图时：

1. **共享 X 轴**的图上下对齐、X 轴只在最下面画一次（`Craft.axis.render` 只在下图调用）。
2. **共享 Y 轴量纲**的图必须用同一个 Y 范围，否则视觉比较是骗人的。
3. **主图 + 从图**：一张大的讲主结论，一到两张小的做分解。不要平铺 6 张同等重要的图。
4. **联动**：点击主图的某个系列，从图跟着过滤。用 `Craft.bind` + `chart.update(filtered)` 实现。
5. 每张图都要有自己的标题。别指望读者从上文推断。

## 七、常见的图表谎言

自查这些 —— 它们让图「看起来对」但读出来的结论是错的：

- **截断的 Y 轴**：放大微小差异，看着像剧变。Y 不从 0 开始必须在图注说明。
- **面积图的双重编码**：用面积表示一维数据时，视觉印象是平方级的。
- **3D 饼图**：透视让前面的扇区显得更大。永远不要用。
- **不均匀的时间间隔**：等距排列不等距的时间点。用 `time` 类型让运行时按真实时间铺开。
- **只画到有利的时点**：截断时间范围制造趋势。给足上下文。
- **幸存者偏差**：只画还在的类别，消失的那些不见了。用「其他」兜住。
- **相关性暗示因果**：散点图上画一条回归线就暗示了因果。除非真有因果证据，别画拟合线。

## 八、交付前的自检

- [ ] 这张图回答的是读者真正要做的判断吗？
- [ ] 有没有更简单的编码方式能达到同样效果？
- [ ] Y 轴是否从 0 开始？不是的话图注说明了吗？
- [ ] 分类数 ≤ 8？超过的归并了吗？
- [ ] 颜色之外还有区分线索吗？
- [ ] 单位写在轴标题里了吗？
- [ ] 数据来源和「示意数据」声明写进图注了吗？
- [ ] 把图关掉只看标题，读者知道它在讲什么吗？
