# 参考文档索引

## 文件清单

### 1. [产物契约](./references/authoring-contract.md)

`SKILL.md`、`references/*`、`scripts/check.mjs` 三者之间的**唯一接口**。写产物之前必读。涵盖：

- 产物硬约束（单文件、零外链、体积、离线、主题、动效、可访问性）
- **槽位协议** —— 四个哨兵槽各放什么；`data-craft-owned` 区域所有权划分
- **`data-*` 契约** —— 容器／数据／图表／控件／分步／图解／模拟，逐属性的必需性与取值
- 运行时速查（比例尺、坐标轴、图表、控件绑定、颜色、格式化、动效）
- 验收清单
- **失败 → 修复表** —— 40+ 条诊断码逐条对应怎么修
- checker 明确**不做**的事（以及为什么不做）

### 2. [图解模型契约](./references/diagram-model.md)

做 `diagram`（技术图解）时读。涵盖：

- 容器与两种模型写法（JSON 块 / `data-*` 属性）
- 通用字段：`nodes` / `edges` / `groups` / `views`
- **六个子类型**（architecture / workflow / sequence / dataflow / lifecycle / freeform）
  各自的字段、节点种类、必需项与完整示例
- 可访问性要求
- 图解专属的失败 → 修复表（含 `layout/*` 几何诊断）
- 为什么模型里没有坐标

### 3. [数据可视化语法](./references/visualization-grammar.md)

做 `chart` 与看板时读。涵盖：

- 按「读者要做什么判断」选图表类型
- 条形/折线/堆叠/热力/散点的细则
- 坐标轴规则（Y 轴起点、刻度数、单位位置）
- 三套颜色令牌的选择与上限
- 标注策略
- 看板的多图联动
- **常见的图表谎言** —— 截断 Y 轴、3D 饼图、面积双重编码、幸存者偏差等

### 4. [可探索解释与模拟](./references/explainer-craft.md)

做 `explainer` 与 `simulation` 时读。涵盖：

- 五段叙事结构（钩子→直觉→机制→边界→应用）
- 渐进披露：每步只引入一个新概念
- 控件设计（哪种控件配哪种参数、范围怎么定）
- 状态↔视图联动（纯函数 `simulate(state)` 的重要性）
- `Craft.sim` 建模与三个常见错误
- 分步叙事的键盘可达性

### 5. [交互模式](./references/interaction-patterns.md)

需要交互设计时读。涵盖：

- **交互模式库** —— tooltip、选中高亮、缩放平移、分步、搜索过滤、深链、动画，每种给适用判据与陷阱
- 交互三原则：默认自解释、可发现、可逆
- 交互的代价：「不加这个，读者会失去什么？」

### 6. [设计系统](./references/design-system.md)

用户指定品牌色/视觉风格时读（**没指定就别读**）。涵盖：

- 完整令牌体系（表面、文字、图形、排版、间距、动效）
- 怎么覆盖品牌色（明暗两套）
- 配色规则与对比度要求
- 排版细则（等宽数值、中文不用斜体、中英混排）
- 可访问性底线
- **AI 生成界面的俗套清单** —— 明确避开

## 使用指南

- **配置时**：只读 `authoring-contract.md` + 对应类型的一份参考 + 一份 `examples/<类型>/skeleton.html`，然后立刻动手写产物。
- **不要预先全读**：六份参考全读一遍会吃掉大量上下文，而且其中五份与当前任务无关。
- **写图表时**：卡在「该用什么图」查 `visualization-grammar.md`。
- **写图解时**：字段与子类型查 `diagram-model.md`。
- **写解释时**：卡在「怎么让读者自己得出结论」查 `explainer-craft.md`。
- **加交互时**：先问「不加会失去什么」，答不上来就删掉。
- **改配色时**：只覆盖令牌，不要写死颜色 —— `check.mjs` 会拦。
- **校验失败时**：查 `authoring-contract.md` 第六节的失败→修复表。

## 与运行时源码的关系

`assets/template.html` 里的运行时是**实现**，不是文档。第一个候选落地之前不要读它。

只有两种情况需要翻：遇到无法解释的内部诊断，或两轮定向修复都失败。

`check.mjs` 的 `artifact/runtime-stale` 规则保证产物携带的运行时与模板逐字节一致 ——
所以文档描述的运行时行为，就是产物里真实运行的行为。

## 理论基础

- **数据可视化**（Tufte, Cleveland & McGill）：视觉编码的感知效率差异，图形完整性
- **探索式数据分析**（Tukey）：让读者自己操作数据得出结论，而非接受预设结论
- **可探索解释**（explorable explanations, Bret Victor）：通过即时反馈建立直觉
- **渐进披露**（progressive disclosure）：一次只给一个新概念，降低认知负荷
- **WCAG 2.1**：对比度、键盘可达性、非颜色线索、减少动效
- **确定性交付**：机器可读的校验回执 + 有牙的门禁，胜过「看起来没问题」
